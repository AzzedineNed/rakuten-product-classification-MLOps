# ---------------------------------------------------------------------------
# CI test dependencies — a deliberate SUBSET of requirements.txt.
#
# The suite is torch-free, mlflow-free and data-free: every import of
# torch / mlflow / requests / tqdm / dotenv inside src/ is lazy (inside a
# function or a try/except), so none of them is needed to import and test
# rakuten_common / rakuten_img / rakuten_text.
#
# Omitted on purpose (installed by requirements.txt, never touched by tests):
#   mlflow, dagshub, dvc, dvc-http     -> tracking & data versioning
#
# THE API LAYER IS NOW INSTALLED HERE, and this is a reversal — it used to be
# omitted with the note "no test imports api/". That was true and it was the
# problem: api/image_main.py, api/text_main.py and api/gateway_main.py were the
# only untested code in the project, and they are the part that serves traffic.
# tests/test_text_api.py imports api.text_main; without fastapi it would SKIP in
# BOTH CI jobs and disappear from CI without a sound, which is the exact failure
# this file was written to prevent. httpx is here for fastapi's TestClient.
#
# prometheus-client IS installed here, unlike the rest of the serving stack.
# tests/test_observability.py drives the metrics middleware at the ASGI level
# and is deliberately fastapi-free even now, so the instrumentation keeps its
# own coverage independent of whether the API layer is installed.
#   torch, torchvision                 -> not in requirements.txt at all
#
# MEASURED: full requirements.txt = 128s / 192 packages / 995 MB.
#           this subset before the API layer =  ~30 packages / 471 MB.
#           this subset now                  =   64 packages / 532 MB.
#           The jump is fastapi 0.111.0 pulling fastapi-cli -> typer/rich/
#           uvicorn. It cannot be trimmed without changing what production
#           installs. Read install TIME off the Actions run, not a laptop.
#
# EVERY PIN HERE MUST MATCH requirements.txt EXACTLY.
# scripts/check_ci_pins.py enforces that and CI runs it before installing.
#
# scikit-learn==1.4.2 is LOAD-BEARING, not cosmetic: rakuten_img.classifier
# passes multi_class= to LogisticRegression, which was removed in newer
# scikit-learn. On 1.9.0 the suite fails with
#   TypeError: LogisticRegression.__init__() got an unexpected keyword
#   argument 'multi_class'
# in tests/test_pipeline.py::test_classifier_roundtrip_and_reorder.
# Unpinning this turns CI red. Fix the source first, then move the pin.
# ---------------------------------------------------------------------------
